# cloudflare-workers-template

A production-minded, framework-agnostic starter template for [Cloudflare Workers](https://developers.cloudflare.com/workers/):
TypeScript, Vitest running inside `workerd`, the [oxc](https://oxc.rs) toolchain (oxlint with type-aware rules + oxfmt) and
CI — wired up and green from the first clone.

## Use this template

Click **Use this template** on GitHub, or:

```sh
npx degit marr-cloud/cloudflare-workers-template my-worker
cd my-worker
pnpm install
```

Then rename the project in two places and regenerate types:

| File             | Field  |
| ---------------- | ------ |
| `package.json`   | `name` |
| `wrangler.jsonc` | `name` |

```sh
pnpm cf-typegen
```

## Requirements

- Node.js — the version in [`.node-version`](.node-version) (minimum `>=22.12.0`)
- pnpm — the version pinned by `packageManager` in [`package.json`](package.json); `corepack enable` picks it up automatically
- A [Cloudflare account](https://dash.cloudflare.com/sign-up) to deploy

## Quick start

```sh
pnpm install
pnpm dev      # http://localhost:8787
pnpm check    # lint + format + typegen + typecheck + test
```

## Scripts

| Script                  | What it does                                              |
| ----------------------- | --------------------------------------------------------- |
| `pnpm dev`              | Local dev server via `wrangler dev`                       |
| `pnpm test`             | Run the suite once (used by CI)                           |
| `pnpm test:watch`       | Run the suite in watch mode                               |
| `pnpm typecheck`        | `tsc --noEmit` over `src/` **and** `test/`                |
| `pnpm lint`             | oxlint, type-aware ([`.oxlintrc.json`](.oxlintrc.json))   |
| `pnpm lint:fix`         | oxlint with autofix                                       |
| `pnpm format`           | oxfmt write ([`.oxfmtrc.jsonc`](.oxfmtrc.jsonc))          |
| `pnpm format:check`     | oxfmt check (used by CI)                                  |
| `pnpm cf-typegen`       | Regenerate `worker-configuration.d.ts` from bindings      |
| `pnpm cf-typegen:check` | Fail if `worker-configuration.d.ts` is stale (used by CI) |
| `pnpm check`            | Every gate, in the same order CI runs them                |
| `pnpm deploy`           | `wrangler deploy`                                         |

## Project structure

```sh
src/index.ts              Worker entry point (fetch handler)
test/index.spec.ts        Tests, executed inside workerd via @cloudflare/vitest-plugin
wrangler.jsonc            Worker config: bindings, vars, compatibility, observability
worker-configuration.d.ts GENERATED by `pnpm cf-typegen` — never edit or format by hand
.oxlintrc.json            Lint rules and plugins (type-aware via oxlint-tsgolint)
.oxfmtrc.jsonc            Formatter options and ignore patterns
.github/workflows/        CI (every push/PR), deploy (manual), Dependabot typegen
AGENTS.md                 Instructions for AI coding agents working in this repo
```

## Adding a binding

Bindings are the in-process handle to KV, R2, D1, Queues and the rest — always prefer them
over calling the Cloudflare REST API from inside a Worker.

1. Add the binding to [`wrangler.jsonc`](wrangler.jsonc) (commented examples are in the file).
2. Run `pnpm cf-typegen`.
3. Use it as `env.MY_BINDING` — fully typed, no hand-written `Env` interface.

`worker-configuration.d.ts` is generated output. It is in `ignorePatterns` of
[`.oxfmtrc.jsonc`](.oxfmtrc.jsonc) and [`.oxlintrc.json`](.oxlintrc.json) on purpose: formatting it
produces thousands of lines of spurious diff on the next regeneration. CI runs `pnpm cf-typegen:check`,
so forgetting to regenerate fails the build instead of shipping wrong types.

## Using a framework (Hono)

The template ships with a plain `fetch` handler so it stays framework-agnostic. To use
[Hono](https://hono.dev) instead:

```sh
pnpm add hono
```

```ts
// src/index.ts
import { Hono } from "hono";

const app = new Hono<{ Bindings: CloudflareBindings }>();

app.get("/", (c) => c.json({ message: `Hello World from ${c.env.ENVIRONMENT}` }));

export default app;
```

`CloudflareBindings` is the same generated interface, so `c.env` stays typed. Tests keep working:

- the integration-style test (`exports.default.fetch(...)`) needs no change;
- for the unit-style test, call `app.request("/", {}, env)` instead of `worker.fetch(request, env, ctx)`.

Other routers and frameworks work the same way: export an object (or app) with a `fetch` handler.

## Environment variables and secrets

Non-sensitive values go in `vars` in `wrangler.jsonc` and are committed.

Secrets never go in `wrangler.jsonc` or in source:

```sh
# Local development: copy the example and fill it in (.dev.vars is gitignored)
cp .dev.vars.example .dev.vars

# Production
pnpm exec wrangler secret put MY_API_KEY
```

## Deploying

```sh
pnpm exec wrangler login
pnpm deploy
```

For CI deploys, set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` as secrets on the
`production` environment, then run the **Deploy** workflow. It is `workflow_dispatch`-only by
default; uncomment the `push` trigger in
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) to deploy on every merge to `main`.

## Conventions

- **Formatting** — oxfmt, tabs, 140 columns, sorted imports and `package.json` keys
  ([`.oxfmtrc.jsonc`](.oxfmtrc.jsonc)), with [`.editorconfig`](.editorconfig) keeping other editors in line.
- **Linting** — oxlint with `correctness` and `suspicious` as errors, plus type-aware rules such as
  `no-floating-promises` and `no-misused-promises`: an un-awaited promise in a Worker is work that
  silently gets cancelled when the response ends — `await` it or hand it to `ctx.waitUntil()`.
- **Types** — `strict`, plus `noUnusedLocals`, `noUnusedParameters`, `noUncheckedIndexedAccess`
  and `verbatimModuleSyntax`.
- **Compatibility date** — bump `compatibility_date` in `wrangler.jsonc` deliberately, and
  re-run `pnpm cf-typegen` afterwards.
- **Dependencies** — Dependabot opens weekly grouped PRs. A `wrangler` bump changes the runtime types;
  [`dependabot-typegen.yml`](.github/workflows/dependabot-typegen.yml) regenerates
  `worker-configuration.d.ts` on those PRs, commits it and re-runs CI, so they stay green.
- **Editor** — VS Code recommends the oxc extension; format-on-save and lint fixes use it.
